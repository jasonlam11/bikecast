# BikeCast

Day-ahead hourly demand forecasting for Boston's Bluebikes bike share system. We forecast pickups and dropoffs per station for the next 24 hours and compare three model families: a seasonal baseline, Prophet, and a PyTorch neural network. The goal is an honest, well-tested comparison and one clear operational takeaway (which stations need bikes moved, and when).

Full plan, data sources, evaluation design, and phases: @docs/PLAN.md

## Hard rules

- No XGBoost, LightGBM, CatBoost, or other gradient boosting. My other projects already use XGBoost; this project exists to show different model families.
- No LLM features. This is a pure forecasting project.
- No data leakage. Every feature must be knowable at forecast time. Splits are always by time, never random. All evaluation uses the rolling-origin backtest in PLAN.md.
- Every model is compared against the seasonal baseline on the same backtest windows. If a model doesn't beat the baseline, we report that honestly.
- Raw and processed data never get committed. `data/` is in `.gitignore`. Scripts must be able to rebuild everything from the public sources.
- Exception: `reports/app_data/` holds a small snapshot of model outputs (backtest predictions and station names, no trips) so the dashboard runs right after cloning. It is generated by `make snapshot`, never edited by hand.
- Results in the README must come from `reports/results.md`, which is generated by code, never typed by hand.

## Local constraints

- Disk space on the dev laptop is tight (about 4 GB free). The data pipeline processes one month at a time: download a month, convert it to Parquet, delete the raw CSV, then move to the next month. Never require all raw CSVs on disk at once.

## Stack

- Python 3.12, managed with uv (`pyproject.toml`)
- DuckDB + Parquet for aggregating millions of trips; pandas for modeling
- Prophet for the statistical model; PyTorch for the neural model
- matplotlib / plotly for charts; Streamlit for the dashboard
- pytest for tests; ruff for lint and formatting; GitHub Actions for CI

## Common commands (keep updated)

```

make data MONTHS=202401   # process only the listed months
make features
make eda         # execute notebooks/01_eda.ipynb headless
make backtest    # runs all models on all backtest windows, writes reports/results.md
make error-analysis   # execute notebooks/03_error_analysis.ipynb headless
make rebalancing # writes reports/rebalancing.md
make snapshot    # writes reports/app_data/ for the dashboard
make app         # streamlit run app/streamlit_app.py
make readme      # copy generated results into README.md
make all         # data, features, backtest, rebalancing, snapshot, readme
make test        # pytest
make lint        # ruff check + format --check
```
